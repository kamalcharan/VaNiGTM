## 4. Open item: step 6, Domain

Blocked, and deliberately not built blind.

`vani_tenant_domain.tenant_id` references **`vani_tenant(id)`**, and
`vani_membership.user_id` references **`vani_user(id)`** — a spine separate from
`vn_tenants` / `vn_users`. Writing to it needs either those tables to exist or
an invented mapping between two tenant models.

**One query decides it**, from any client on `vani_gtm_db`:

```sql
\dt vani_*
```

- **Tables exist** → build the Domain screen + its writer in
  `applyStepPayload` (`backend/src/onboarding/onboarding.routes.ts`), flip
  `enabled` in `backend/src/onboarding/lanes.ts`. Both halves in one slice.
- **Nothing** → the spine was never applied. Then it is a decision, not a task:
  apply `docs/vani/sql/001_vani_platform.sql`, or drop Domain and let
  `business_profile.website` carry it.

Step 8 BYOK is blocked on the same spine plus an encryption path —
`vani_llm_provider.credentials_enc` is "encrypted at rest; never pooled across
tenants" and nothing implements that yet.

## 5. Localhost — explicitly requested for the next session

Deferred today by decision (see `vani-app/CLAUDE.md` §0). Picking it back up:

**The mode that works** is local backend + VPS Postgres, and it needs no
production change:

```
# vani-app/.env.local
NEXT_PUBLIC_API_ORIGIN=http://localhost:3002
```
```
cd vanigtm && git checkout main && cd backend && npm install && npm run dev
```

Backend `.env` must have `PORT=3002`, `CORS_ORIGIN=http://localhost:3000`,
`NODE_ENV=development`, `DB_PRIMARY` → the VPS Postgres. No Docker locally —
the backend is `tsx watch src/server.ts`; Docker is only how it runs on the VPS.

**Facts, so they are not rediscovered:**

- The variable is `NEXT_PUBLIC_API_ORIGIN`. VaNiGTM's frontend uses
  `NEXT_PUBLIC_API_URL`, which this app never reads — and the wrong name fails
  **silently** into the mock transport.
- SameSite is about the **domain, not the port**. `localhost:3000` ↔
  `localhost:3002` is same-site, so the `sameSite:'strict'` refresh cookie is
  sent. `NODE_ENV=development` drops `secure`. Auth genuinely works.
- `localhost` → `api.vikuna.io` is cross-site: the cookie is neither sent nor
  storable over http, and `localhost` is not in nginx's
  `map $http_origin $cors_origin` allowlist (which defaults to `""`).

**The unresolved bit.** A previous attempt reached: `/health` ok, VPS Postgres
at 129ms, and `OPTIONS /api/v1/auth/login` returning **204 with
`Access-Control-Allow-Origin: http://localhost:3000`** — and the browser still
failed the login `fetch` at the network layer (`api-client.ts:151`, thrown only
when `fetch` itself throws). Ruled out: backend down, CORS refused, CSP (there
is none; `next.config.ts` sets only `reactStrictMode`).

**Next diagnostic, not yet done:** open DevTools → Network, retry the login,
read the failed request's label. `ERR_CONNECTION_REFUSED` and a CORS block look
identical in the UI and are unambiguous there. Also confirm the port Next
actually bound — if 3000 was busy it silently uses 3001, and `CORS_ORIGIN` is a
single exact-match string.

## 7. Traps that cost hours today — do not relearn

1. **Undefined CSS custom properties do not fall back; the browser discards the
   whole declaration.** Ported screens use VaNiGTM's `--color-*` tokens, injected
   there by a ThemeScript this app lacks. An undefined
   `--color-primary-dim` made the progress spinner's border invisible, so four
   minutes of research looked frozen. Aliases now live in
   `src/styles/globals.css`. **After porting anything, check every `var(--…)`
   resolves** — a build passing proves nothing about this.
2. **A route named only in a comment still needs porting.** `icp-builder` was a
   dangling reference for hours.
3. **Never reveal which model answered.** `agent-core` writes an `llm_failover`
   step carrying the raw error; it is filtered from the feed
   (`INTERNAL_STEPS`). The tenant sees VaNi working. The row is still stored and
   auditable.
4. **The theme is gold, not orange.** `--gold` is "GOLD — VaNi itself"; `--ac`
   orange belongs to `www.vikuna.io`.
5. **Read before inferring.** The wrong image name, the wrong VPS paths, the
   "screens are built" claim, and the non-discriminating 401 probe were all
   inference where a one-line read was available.

## 9. Repos and branches

**Two repos, not three.** `vani-app` is often spoken of as its own project
because it is a separate *Vercel* project, but it is a plain directory in this
repo — 119 tracked files, regular file mode, no gitlink. `.gitmodules` declares
exactly one submodule, `vanigtm`. So `vani-app` needs no separate scope, no
separate branch, and its commits are `vikunawebsite` commits.

| | What it is | Where |
|---|---|---|
| `kamalcharan/vikunawebsite` | the marketing site (`src/`, `public/` → `www.vikuna.io`) **and** `vani-app/` (the console → `vani.vikuna.io`) | this repo |
| `kamalcharan/VaNiGTM` | the backend | submodule at `vanigtm/` |
